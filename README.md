# CS-320

## How can I ensure that my code, program, or software is functional and secure?

I can make sure my code is functional by testing it as I work instead of waiting until the entire program is finished. One thing I learned in this course is that I should test more than just whether my code works with valid information. I also need to test things like null values, incorrect inputs, character limits, and other situations that could cause the program to fail. I also learned that just because all of my tests pass does not mean I tested everything. Going back through the requirements and making sure each one has been tested can help me catch things I may have missed. For security, I think it is important to validate information and think about possible problems before the software is released.

## How do I interpret user needs and incorporate them into a program?

I think the first step is really understanding what the user is asking for and then breaking those requirements into smaller pieces. In Project One, I was given specific requirements for what each service needed to do and what information it could accept. I used those requirements to help me write the code and decide what needed to be tested. This helped me understand that I should not just build something based on what I think the user wants. I need to keep going back to the requirements and make sure the program actually does what was requested.

## How do I approach designing software?

I like to start by understanding what the program needs to do and then break it into smaller parts so it does not feel as overwhelming. From there, I can work on one part at a time and test it before moving on. This course also taught me to think about testing while I am writing the code instead of treating testing as something I only do at the end. I want to continue using that approach because it makes it easier to catch mistakes early and understand which part of my code needs to be fixed when something goes wrong.
